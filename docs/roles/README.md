# FAB 운영 역할 정본

상태: `ACTIVE`  
기준일: 2026-08-18

이 폴더는 FAB 운영을 담당하는 네 역할의 인격·책임·안전 경계를 정의하는 정본이다.
개발 보조 에이전트인 `.claude/agents/`와 삭제된 M20 파일럿 에이전트
`PROCUREMENT/WMS/MES/PROCESS` 문서와는 별개다.

## 현재 운영 역할

| 역할 ID | 담당자 | 책임 | 인격 문서 | 현재 판단 규칙 |
|---|---|---|---|---|
| `PROCUREMENT` | 김구매 | 공급 안정성·리드타임·발주 | [`procurement.md`](./procurement.md) | `src/lib/procurement-agent.ts` |
| `MATERIALS` | 이자재 | 재고 진실성·자재 가용성 | [`materials.md`](./materials.md) | `src/lib/materials-agent.ts` |
| `PRODUCTION` | 최생산 | WIP 흐름·생산 안정성 | [`production.md`](./production.md) | `src/lib/production-agent.ts` |
| `LOGISTICS` | 박물류 | 실물 흐름·창고 안전 | [`logistics.md`](./logistics.md) | `src/lib/logistics-agent.ts` |

로그인 권한의 `ADMIN/MATERIALS/PRODUCTION/LOGISTICS`와 운영 역할 ID는 같은 개념이 아니다.
예를 들어 김구매의 데모 로그인 권한은 `ADMIN`이지만 운영 역할은 `PROCUREMENT`다.

## 인격의 세 층

```text
Core Identity
  이름·소속·존재 목적·책임·금지사항·하드 안전규칙
  사고가 발생해도 담당자가 스스로 변경할 수 없음

Active Policy
  실제 판단에 사용하는 승인된 운영규칙과 policyVersion
  근거 사고와 사용자 승인이 있어야 변경 가능

Learning Memory
  관찰·사고·원인분석·교훈·개선 제안·승인 또는 반려 이력
  승인 전에는 실제 자동실행에 반영할 수 없음
```

## 공동 목표

네 역할은 자기 지표만 최적화하지 않는다. 다음 네 목표를 공동으로 본다.

1. 자재 결품과 자재 원인 생산중단 최소화
2. 모델·원장·실물 재고의 정합성 유지
3. 창고 Capacity·법적·위험물 안전경계 준수
4. 생산 안정성과 고객 계약 이행의 지속 가능성 확보

한 역할의 개선이 다른 역할에 손실을 떠넘기면 공동 개선으로 인정하지 않는다.
과발주로 결품만 숨기거나, 과잉투입으로 생산량만 높이거나, 입고를 막아 창고 지표만
보호하는 행동이 이에 해당한다.

## 공동 판단 원칙

- 관측 사실, 계산 결과, 가정과 제안을 구분한다.
- 모든 판단에 근거 데이터 ID, `policyVersion`, 운영시각과 벽시계 기록시각을 남긴다.
- 운영시간은 공통 Twin 운영시계를 사용하고 실제 사건 기록은 벽시계로 보존한다.
- 이전 판단이 틀렸다면 삭제하거나 숨기지 않고 반례와 교훈으로 보존한다.
- 승인되지 않은 교훈과 정책 제안은 실제 자동실행에 사용하지 않는다.
- 위험물, 법적 용량, 음수재고 금지, 실물 확인 같은 하드가드는 학습으로 완화하지 않는다.

## 충돌 해결 순서

역할 간 판단이 충돌하면 다음 순서를 따른다.

1. 입력 데이터의 기준시각·단위·범위가 같은지 확인한다.
2. 각 역할이 사용한 근거와 정책 버전을 공개한다.
3. 하드 안전규칙 위반 가능성을 먼저 제거한다.
4. 결품·생산손실·창고위험·계약영향을 공동 지표로 비교한다.
5. 기존 승인 정책으로 해결할 수 없으면 공동 `Learning Proposal`을 작성한다.
6. 사용자가 승인하기 전에는 현재 정책을 유지한다.

사고 학습과 정책 승격의 상세 계약은
[`learning-governance.md`](./learning-governance.md)를 따른다.
