# FAB 운영 역할 사고 학습·승인 계약

상태: `ACTIVE`  
버전: `OPERATION_ROLE_LEARNING_GOVERNANCE_V1`  
기준일: 2026-08-18

## 목적

김구매·이자재·최생산·박물류가 운영 문제를 반복하지 않도록 사고와 교훈을 누적하되,
담당자가 자기 인격이나 실제 자동실행 정책을 승인 없이 변경하지 못하게 한다.

## 학습 상태

```text
OBSERVED
  운영 이상 또는 사람의 문제 제기가 사실로 기록됨
    ↓
ANALYZED
  네 역할의 원인 분석과 공동 영향 범위가 연결됨
    ↓
PROPOSED
  변경 대상·예상 효과·회귀 위험·검증방법이 있는 개선안 작성
    ↓
APPROVED ───────────────→ REJECTED
  사용자 승인                반려 이유와 당시 근거 보존
    ↓
ACTIVE
  새 policyVersion으로 실제 판단에 반영
    ↓
SUPERSEDED
  후속 승인 정책으로 대체되었지만 재현을 위해 보존
```

담당자는 `OBSERVED → ANALYZED → PROPOSED`까지만 자동으로 진행할 수 있다.
`APPROVED` 전환 권한은 사용자에게만 있다.

## 사고 한 건의 필수 정보

- `incidentId`, 제목, 심각도와 최초 탐지자
- 실제 `recordedAt`과 사고가 영향을 준 Twin 운영시간 구간
- 당시 재고·WIP·PO·창고·계약 스냅샷의 근거 참조
- 참여 역할별 판단, 사용한 `policyVersion`과 실행 행동
- 결품·생산손실·과잉재고·창고위험·계약영향 결과
- 사람이 수행한 승인·반려·수량수정·강제해제와 이유
- 직접 원인, 기여 원인, 탐지를 놓친 원인
- 개선 대상 역할과 다른 역할에 미치는 영향

## 개선 제안의 필수 정보

- `proposalId`, 근거 `incidentIds`와 제안 역할
- 변경할 정책 필드와 이전값·제안값
- 해결하려는 실패 유형과 예상 효과
- 결품·생산·창고·계약 지표의 예상 변화
- 하드 안전규칙 검증 결과
- 과거 사건 재생 테스트와 그림자모드 검증 방법
- 승인자, 승인 벽시계 시각과 새 `policyVersion`

단순히 “다음에는 주의한다”, “더 많이 발주한다”, “임계값을 조정한다”처럼 변경 대상과
검증방법이 없는 제안은 `PROPOSED`가 될 수 없다.

## 자동 변경 금지 대상

- 역할 ID·담당자 정체성·소유 책임
- 위험물·법적 Capacity·혼재금지 경계
- 음수재고·이중입고·단위 혼합 금지
- 실물 확인과 감사 이력 보존 의무
- 공통 Twin 운영시간 24×와 벽시계 분리 원칙
- 사용자 승인 권한 자체

## 공동 사고 규칙

다음처럼 역할 사이 인과가 이어지면 한 역할의 단독 사고로 분리하지 않는다.

```text
김구매 과발주
→ 박물류 Capacity 초과·입고보류
→ 이자재 가용재고 부족
→ 최생산 WIP 차단
```

공동 사고는 역할별 원인을 따로 기록하되 하나의 `incidentId`와 결과 지표를 공유한다.
한 역할의 지표가 좋아져도 공동 결과가 악화되면 개선으로 승인하지 않는다.

## 저장 경계

인격과 책임의 정본은 `docs/roles/`에 둔다. 현재 실행 정책은 각 `*-agent.ts`와 Twin 실행
모듈에 버전으로 남긴다. 런타임 학습을 구현할 때 MongoDB 컬렉션은 다음 책임으로 분리한다.

| 컬렉션 | 책임 |
|---|---|
| `operationIncidents` | 운영 이상·근거·역할별 분석·실제 결과 |
| `operationLearningProposals` | 개선 제안·예상 효과·재생 검증 결과 |
| `operationPolicyRevisions` | 사용자 승인·반려·활성·대체 이력 |

기존 `controlTowerAIEpisodes`는 당시 스냅샷과 자문 대화 기록으로 유지한다. 결과와 정책 승격이
없는 자문 기록이므로 위 세 컬렉션을 대체하지 않는다. 삭제된 M20 파일럿의 `agentRuns`와
`agentDecisions`도 현재 네 역할의 학습 원장으로 재사용하지 않는다.
